# Decisions (flybot-aws)

One line per technical choice, newest last.

| Date | Decision | Why |
|---|---|---|
| 2026-10-16 | Vision Lambda is **stateless**: one invocation = one photo; memory stores seeded from the request (`history`), proposals returned in the response, no DynamoDB / SQS / Step Functions / EventBridge (modules deleted) | FlyBot (MongoDB) already owns cameras, snapshots, approvals and traces; the Lambda only needs one photo and the camera's recent counts (SIMPLIFY_PLAN W2) |
| 2026-10-16 | The agent's device / FlyBot tools answer "pending" and every accepted action tool call becomes a contract **proposal** (`sentinel/agent/proposals.py`: capture_now, set_isp, set_interval, review_request, notify); RulePlanner and LLMPlanner unchanged, guardrails still run before each call | Keeps the perception -> decision -> guarded action -> trace loop of the first build; FlyBot applies or asks the grower (confirm cards) |
| 2026-10-16 | `requiresApproval`: capture_now / notify / review_request false, set_isp / set_interval true; `confidence` per decision-rule prefix (policy.yaml `proposal_approval`, `proposal_confidence`) | One extra photo within the guardrails' budget is low risk; camera settings and schedules touch battery and image quality. Policy choices written in the policy file, not measurements |
| 2026-10-16 | Error contract: raise `VisionError` subclasses whose `str()` is the contract JSON (FunctionError `errorMessage`), `errorType` = the code in CamelCase; the local server maps them to HTTP 400/404/503/500 | Lambda `Invoke` has no status code; FlyBot reads one field either way (CONTRACTS.md 1a) |
| 2026-10-16 | Photos are decoded **before** the agent runs (`IMAGE_CACHE`) so `photo_not_found` / `bad_request` are reported as such and the bytes are fetched once | The agent's `analyze_trap_photo` turns exceptions into tool errors, which would hide a missing photo as `internal` |
| 2026-10-16 | Detector by env `DETECTOR=yolov7|yolo26` (`sentinel/vision/detector.py`); YOLOv7-tiny baked into the image, YOLO26 fetched at cold start from the public model bucket (SHA-256) or baked when `models/yolo26/` exists at build time | The YOLO26 weights do not exist until the owner runs the Colab notebook; the Lambda must work on day 1 |
| 2026-10-16 | `detect_yolo26.py` decodes both the end-to-end `[1,300,6]` head and the one-to-many `[1,4+nc,A]` head (NMS in Python) | The fallback for ops unsupported by the new DNN engine needs no code change, only a different export (`verify_yolo26.py`, COLAB_RUNBOOK.md) |
| 2026-10-16 | LLM: Anthropic API `claude-haiku-5-5` through Secrets Manager `sentinel-dev-anthropic` (ANTHROPIC_SECRET_NAME), prompt caching on; deep mode always tries the LLM, detect mode uses the rule planner unless `PlannerMode=llm`; any LLM failure -> rule planner + a templated `answer` | Bedrock InvokeModel is still blocked on the account (AWS_ACCOUNT.md); the rule planner keeps detect mode deterministic and free |
| 2026-10-16 | Weather (Open-Meteo) off in the Lambda (`SENTINEL_WEATHER=off`): the surge rule still fires (`notify` / review); the spray-plan treatment proposal needs weather + GPS and only appears when the owner turns it on | No outbound dependency per photo; FlyBot has its own weather service for the chatbot |
| 2026-10-16 | SAM stack `flybot-<stage>` in **two phases** (`ImageUri` empty -> no Lambda yet) and the arm64 image is built **on the FlyBot EC2 through SSM Run Command** (`infra/build-image.sh`), context uploaded to the photos bucket `build/` | No Docker on the laptop and ~2 GB free disk; the t4g.small is arm64 with Docker already (user-data), so no builder instance or CodeBuild project is needed. CodeBuild (`ARM_CONTAINER`) is the documented alternative |
| 2026-10-16 | FlyBot EC2: AL2023 arm64 from the SSM public AMI parameter, SSM Session Manager (no SSH key needed; port 22 only from `OwnerCidr`), IMDSv2 hop limit 2 | Containers (FlyBot) read the instance role through IMDSv2; no keys on the box |
| 2026-10-16 | IoT: thing type `camos-camera`, policy `camos-camera-<stage>` (camos/<thing>/... topics + the thing's classic shadow and jobs topics); HTTPS topic rules to FlyBot only when `DeviceEventsWebhookUrl` is set | Agent F's primary path is an MQTT-over-WSS client with SigV4; the rules are its documented fallback and need a one-time destination confirmation by FlyBot |
| 2026-10-16 | Alarms: Lambda errors (>= 3 in 5 min), Lambda p90 duration > 30 s, EC2 status check; topic reused from `sentinel-dev-alarms` when `EXISTING_ALARM_TOPIC_ARN` is given (its email is confirmed), else a new topic + email subscription | The owner already confirmed one subscription; a second email would need another click |
| 2026-10-16 | Tests of the first build that needed DynamoDB/IoT/FlyBot HTTP/MCP/eval-root imports were deleted (10 files); `eval/replay.py`, `failure_injection.py`, `run_eval.py` stay but need adapting to the handler (`eval/replay_sample.py` is the working path) | They tested transports that no longer exist; the vision-op and agent tests (185) remain |
| 2026-10-16 | FlyBot's environment is **written by the stack**: user-data (re)writes the stack-managed keys of `.env` (IOT_ENDPOINT, KVS_VIEWER_ROLE_ARN, FLYBOT_SECRETS, PHOTOS_BUCKET, VISION_LAMBDA_NAME, AI_PROVIDER, DOMAIN_NAME, APP_BASE_URL, ...) on every run; `deploy.sh` looks the IoT Data-ATS endpoint and the newest AL2023 arm64 AMI up with the CLI and passes them as parameters | The public SSM AMI alias is not readable in this account (`ParameterNotFound`) and the IoT endpoint is an account fact CloudFormation cannot resolve; one `make deploy` must leave a working host without hand edits |
| 2026-10-16 | Application secrets live in Secrets Manager `flybot-<stage>-app` (stack resource, JWT_SECRET generated, the rest placeholders the owner fills) and the Google service account in `flybot-<stage>-gcp`; FlyBot reads them at start-up with the instance role; the only secret-like value in `.env` is the optional IoT rule secret | Nothing to copy by hand on the box, no secret in git or in the user-data; the chatbot's Vertex client needs a file, so that one secret is materialised (mode 600, uid 1000) only when it holds a `private_key` |
| 2026-10-16 | KVS live view: a dedicated role `flybot-kvs-viewer-<stage>` (viewer actions on `channel/cam-*/*`) that only the instance role may assume; FlyBot narrows each 15-min session to one channel with a session policy | The browser never holds the instance role's credentials; blast radius = one channel for 15 minutes |
| 2026-10-16 | `set_isp` only for `camera.platform == "camos"`; evidence JPEGs go to the bucket the photo came from | FlyBot refuses ISP changes on EZVIZ and signs evidence keys against its own bucket |
| 2026-10-16 | Detector = **YOLO26n end-to-end head on OpenCV 5 DNN (new engine)**, `DETECTOR=yolo26`; YOLOv7-tiny kept as baseline and AMB82 edge model | Test mAP@50 0.953 vs 0.958 (within noise), mAP@50-95 0.700 vs 0.67, same counts on the 24 sample photos, DNN 1.4x faster, no NMS code; the end-to-end graph matches ONNX Runtime detection for detection (eval/results/yolo26*_parity*.json) |
| 2026-10-16 | **One command, one settings file**: `deploy.env` (git-ignored, refused by the pre-commit scan) + `./deploy.sh` with steps preflight, discover, models, secrets, stack, image, lambda, bootstrap, health, smoke, coldstart, summary; `--dry-run`, `--only`, `--show-ip`, `--yes` | The owner fills one file once; everything the AWS CLI can look up or create (IoT endpoint, AMI, public IP, confirmed alarm topic, quotas, secrets, model upload, image build) is done by the script, idempotently |
| 2026-10-16 | Secrets `flybot-<stage>-app/-gcp/-anthropic` are owned by the script, not by the stack: merged from deploy.env (non-empty values win, keys added in the console are kept), JWT and VAPID generated once, written only when the content changed | CloudFormation would either regenerate or ignore them; the script can compare without printing values and destroy can keep them |
| 2026-10-16 | Lambda image tag = hash of the build inputs (`lambda/vision/sentinel`, Dockerfile, requirements, models); the build on the EC2 runs only when that tag is not in ECR | Re-running deploy.sh costs nothing when the code did not change, and works from any machine |
| 2026-10-16 | The AMI is pinned by the stack after the first deploy (AmiId parameter reused); the photos bucket is retained on stack deletion and reused (`PhotosBucketExists`) | A newer AMI or a stack recreate would otherwise replace the instance (MongoDB on its root disk) or lose the photos |
| 2026-10-16 | DNS stays manual at Namecheap: the record is printed in a box as soon as phase 1 has the Elastic IP, and the health step polls 1.1.1.1 / 8.8.8.8 (DNS over HTTPS) for up to 30 min before checking the certificate with `curl --resolve` | agrhub.com is not in Route 53 and the owner keeps the registrar; the long image build covers the propagation time |
| 2026-10-16 | Instance role for self-registration (CONTRACTS 2a): CreateCertificateFromCsr (no resource scoping in IAM), thing actions on `thing/*` + `thingtype/camos-camera`, certificate/policy actions on `cert/*` + `policy/camos-camera-<stage>`, KVS on `channel/cam-*/*`; device policy Connect requires `iot:Connection.Thing.IsAttached` | FlyBot is the only party that talks to IoT for public cameras; each certificate can only act as its own thing |
| 2026-10-16 | **Open-core split** (owner): agrhub/flybot (FlyBot app, submodule `flybot/`) becomes private and proprietary; flybot-aws (AGPL-3.0) and camos-esp32-trap stay public; AMB82 firmware, production datasets and production weights stay private. The Lambda, infra, bench, eval and the sample replay never need the submodule | The competition entry stays reproducible in public while the commercial app is not published |
| 2026-10-16 | The EC2 reads the private submodule with a read-only **deploy key** that deploy.sh generates once (ed25519, private half in Secrets Manager `flybot-<stage>-deploykey`, public half printed with the exact GitHub path, access polled until it works) or a fine-grained PAT (`FLYBOT_REPO_TOKEN`, Contents read-only). The host fetches it at bootstrap into /root/.flybot-git (700/600), pins GitHub's ed25519 host key, passes the ssh rewrite with `git -c url.insteadOf` and deletes the key after the update; `.gitmodules` stays https | Least privilege (one repo, read-only), nothing secret on disk after boot, people with access keep cloning over https |
| 2026-10-16 | Detector plan: the competition demo runs **YOLO26n** (AGPL-3.0 weights, public under `models/yolo26/` of the public model bucket); after the contest the commercial build moves to **RF-DETR** (Apache-2.0 code) with AGRHUB-trained weights in a private bucket | The public entry stays fully open and reproducible; the commercial model and its training data stay private |
